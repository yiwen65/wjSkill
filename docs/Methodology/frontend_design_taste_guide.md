# 前端设计品味指南

2026-09-01｜适用营销页与Web应用。继承既有品牌和系统；不要为原创破坏熟悉交互。先完成真实任务与内容，再做视觉表达。

**标记：硬＝适用的 WCAG 要求；约＝项目默认，可说明理由后调整；品＝有依据的偏好，须检验反例。未标“硬”的数值不是普适标准。**

## 一、核心原则

### 排版
- **约：**按标题、正文、标签、数字定义字阶和字重，复用少量字体。检：同角色一致，中英文、标点、回退字体均正常。反：全部16px、全部加粗，或为新奇混用字体。[^T]
- **约／品：**按任务选字号；16px可作正文起点，紧凑界面另验。长段落试1.5–1.8行高并限制行长。检：实读多行、窄屏与放大状态。反：把16px当WCAG下限，把英文字符数照搬为汉字数。[^T][^W]
- **约：**数字统一单位、精度和本地化；比较列右对齐或按小数点对齐，必要时用等宽数字。检：负数、空值、大数、混排和标点断行。反：用空格对齐，把未知写成0；等宽数字不会自动对齐小数点。[^C]

### 色彩
- **硬：**一般文本对比≥4.5:1；大文本≥3:1，通常至少24CSSpx或18.67CSSpx粗体；不确定按4.5:1。必要控件／状态识别信息与相邻色≥3:1。检：实测各主题、状态和实际背景，渐变不取平均。反：浅灰小字、认为所有装饰边框都必须3:1。[^W]
- **约：**建立背景、表面、主／次文字、动作、焦点、状态等语义色，逐主题映射。检：同义同色，深色单独验证。反：全局反相；用红色表达所有重要信息。
- **品：**让强调色和材质服务品牌、层级或状态。检：说清每种渐变、玻璃、阴影的作用。反：默认禁用紫色，或无理由给所有区域加光晕。材料不是原罪。[^R]

### 布局
- **约：**采用有限间距尺度，相关项靠近，组间距离通常更大；共享主要对齐线。检：相同关系是否同距，例外是否必要。反：任意间距；把1px边框、2px光学校正也强改为8倍数。[^S]
- **约／品：**独立对象可用卡片，跨记录比较优先表格，连续内容用列表／正文。检：每条边界能否解释对象或交互范围。反：卡片套卡片；把后台套成大留白海报。[^R]
- **约：**按内容破点调整列、导航、密度；保留核心任务。检：连续缩放并测试长文本、错误和空态。反：只验两个预设宽度；移动端删掉关键字段。[^B]

### 层级
- **品：**让最大视觉权重对应最重要的信息；每个决策区域有明确主要动作。检：用户能否指出标题、证据和下一步。反：所有按钮同样醒目，或要求整个复杂应用只能有一个主按钮。[^R]
- **品：**短hero可居中；长正文、表单按阅读方向起始对齐。检：扫描起点稳定、DOM顺序合理。反：整页居中；把F型当强制布局；为对称补无意义模块。

### 动效
- **约／品：**只保留反馈、方向、连续性或明确品牌用途的动效。短反馈可先试120–180ms，再按距离、尺寸、频率调整。检：连续操作不排队、不等装饰结束。反：所有元素弹跳；把推荐时长当规范。[^M]
- **约：**响应`prefers-reduced-motion`，保留终态和功能；测实际绘制与输入。检：减少动态效果时仍可完成任务。反：关闭动画后内容透明；业务依赖`animationend`；认为transform必然零成本。[^M]

### 一致性
- **约：**复用语义token和组件契约，覆盖默认、聚焦、选中、禁用、加载、空、错、成功。检：同类组件跨页行为一致。反：只统一颜色；把组件库当完整设计系统。[^D]
- **品：**让文字、图像、图标与材料共享品牌方向。检：每项能解释用途，截图之外也成立。反：emoji随意充当功能图标、混用图标笔画；系统字体本身不算错。

## 二、交互与无障碍底线

以下非完整WCAG审计。[^W]

- **硬：**优先原生按钮、链接和输入；保证名称、角色、状态、输入标签、文字错误及适当状态通知。键盘可完成任务，焦点可见且组件不被完全遮挡；颜色不能是唯一线索。装饰图像不制造无意义朗读。
- **硬／约：**一般目标满足24×24CSSpx；小目标仅在核对2.5.8间距、行内等例外后接受，测实际命中区。触控优先44×44是增强建议，不是AA统一门槛。2px焦点环可作起点，但不自动证明符合AAA。
- **硬：**文本放大200%不丢内容／功能；适用内容在等效320CSSpx宽重排，必要二维区域局部处理。用户覆写行高1.5、段后距2、字距0.12、词距0.16倍字号时，适用语言项目不丢内容／功能；这些不是默认CSS要求。
- **约：**模态打开时正确入焦，内部循环，背景不可操作，关闭后合理返回焦点。不要只写ARIA属性而漏行为。[^A]
- **硬：**适用悬停内容可关闭、可移入、可持续；拖动提供非拖动单指针替代；登录支持适当辅助／替代，不禁密码粘贴。自动运动与更新检查2.2.2；不要把“少于5秒”当所有更新的豁免。非必要交互动效可关闭的2.3.3是AAA，不冒称AA。

## 三、常见错误 → 后果 → 修正

以下为风险模式，非频率排名。

1. 无理由紫色渐变 → 品牌和层级被模板覆盖 → 先定义角色，再决定保留或删除。
2. 功能图标用无名称emoji → 意义及风格不稳定 → 统一图标并提供可访问名称。
3. 万物卡片化 → 关系切碎、比较困难 → 按数据关系改表格、列表或正文。
4. 全居中、全加粗 → 扫描与主次消失 → 恢复对齐线、字阶和主要动作。
5. 浅灰小字“高级感” → 难读或不合格 → 先恢复对比，再调整视觉权重。
6. 任意间距、无限留白 → 分组不清或效率低 → 复用尺度，按任务调整密度。
7. 固定高度加裁剪 → 长文、放大、错误被吞 → 内容撑高；截断须有完整访问途径。
8. placeholder唯一标签 → 输入后丢失字段意义 → 保留可见标签和关联说明。
9. 只做hover与理想状态 → 键盘、触控、失败路径不可用 → 补齐状态和操作替代。
10. 深色反相、层层玻璃 → 语义失真、背景不稳定 → 独立主题映射和稳定文字承载面。
11. 无理由装饰动画 → 分心、等待、性能成本 → 删除或降级，保留即时反馈。
12. 假数据／logo／好评 → 制造错误信任 → 使用真实证据；开发样例明确标注。
13. 一张截图或自动高分即交付 → 未测流程被误认为完成 → 做人工操作和边界测试，列明未测项。

## 四、生成后自检：逐项回答“是／否”

未知按“否”；不适用须记理由。先修任务／无障碍，再修层级，最后润色。未实际操作，不写“已测试”。

- [ ] 页面对象、核心价值或任务、下一步是否明确，内容与证据是否真实？
- [ ] 主要强调是否对应任务，同角色字阶／间距／颜色／组件是否一致？
- [ ] 长文、数字、中西混排、图标与字体回退是否已用真实样本检查？
- [ ] 卡片、留白、居中、材质与动效是否各有用途，而非填空？
- [ ] 所有适用文本、控件、状态在各主题和实际背景下是否实测对比达标？
- [ ] 仅用键盘能否完成主流程，焦点可见、顺序合理且不被完全遮挡？
- [ ] 标签、名称、状态、错误及模态是否经过读屏及可访问树检查？
- [ ] 目标大小、悬停、触控和拖动替代是否满足适用要求？
- [ ] 200%文本、等效320px重排和文本间距覆写是否均通过？
- [ ] 长内容、加载、空、错、成功、禁用及权限状态是否不丢任务信息？
- [ ] 减少动态效果时功能是否完整，自动运动是否有适用控制？
- [ ] 是否测过实际加载／输入／绘制，未把实验室高分当完整合规证明？
- [ ] 是否记录测试条件、失败修正、例外及尚未验证的范围？
