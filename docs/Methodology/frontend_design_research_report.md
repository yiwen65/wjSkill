# 通用 Web 前端设计：方法论、美学与错误修正

**面向：** 前端工程师、产品设计师、设计负责人及生成界面的 AI agent  
**范围：** 营销页／落地页与 Web 应用；兼顾中文、拉丁文字、桌面和移动环境  
**调研与版本基准：** 2026-09-01  
**配套成果：** 《前端设计品味指南》是一份独立执行规范；本报告提供其证据、例外和推导边界。

## 摘要：值得固化的不是一种外观，而是一套决策次序

本报告提出的工作次序是：**先确定用户任务和真实内容，再建立信息层级；用排版、间距和语义色表达关系；最后选择有品牌理由的视觉材料与动效；全过程验证无障碍、响应式及真实状态。** 这是综合成熟实践得出的工作建议，不是经过对照实验验证的唯一流程。Double Diamond 的发散／收敛框架、Refactoring UI 的功能与层级导向，以及 Carbon 的情境化排版，为这一综合提供依据。[^C05][^C02][^T02]

“品味”可以转成可检查的决策，但不能全部转成普适阈值。正文对比度可以测量；某品牌是否适合衬线字、是否值得使用大面积渐变，则须比较任务、语境、可识别性与成本。**用审美偏好取代可访问性是错误，用可访问性合格证明审美优秀也同样错误。**[^A02][^J03]

本报告尤其拒绝五种简化：把 16px 当全 Web 最小字号；把 8pt 当强制网格；把 44×44 当 WCAG AA 的统一门槛；把 WCAG 文本间距覆写测试当默认 CSS；把紫色、渐变、卡片或系统字体本身判为低级。前四项必须核对条款或约定，最后一项必须核对具体用途。[^T04][^L01][^A08][^A09][^A05][^V01][^J10]

## 0. 方法、证据等级与适用边界

### 0.1 如何区分“有出处”与“已证明有效”

全文使用两个维度，不能混为一谈：

| 标记 | 含义 | 如何验收 |
|---|---|---|
| **R：规范规则** | 在所声明的适用范围内有明确要求，例如 WCAG 2.2 AA | 按原条款、适用条件和例外测试；注明 A／AA／AAA |
| **C：工程／系统约定** | 团队为一致性选择的字号、间距、状态、token 结构 | 与项目配置和组件契约比对；可测试，但不是自然法则 |
| **J：品味判断** | 有理由的表达偏好，例如用更强的版式而非更多装饰建立特色 | 指认意图，比较替代方案，检查反例，再通过任务或品牌评审验证 |
| **证据 A** | 规范原文或可直接核验的一方事实 | 强在“条款／该案例确实如此”，不自动证明适用于所有产品 |
| **证据 B** | 成熟系统实践、经典方法或有范围限制的研究观察 | 可作可靠起点；必须保留使用语境 |
| **证据 C** | 本报告的综合、建议区间、判断实验 | 明确作为待验证假设，不包装成研究结论 |

下文的“判断方法”是本报告设计的验收办法；除特别注明外，**不是文献已经做过的实验**。错误章节列出风险模式，不声称是经过抽样统计的发生频率排名。

### 0.2 检索与交叉核验

研究分三轮：先查经典方法、WCAG 与成熟设计系统；再查设计团队的一方案例及风格说明；最后复核容易被误传的数字、等级、发布状态和术语。来源优先 W3C、设计系统与浏览器文档、作者／出版社和创作团队，使用奖项与风格评论时明确其选择偏差。

停止检索的依据是：三个主线均已有可用证据，关键数字已追到原条款，重要冲突已澄清或保留。没有开展互联网全量样本分析、真实用户实验、设备实验室测试或付费书籍全文考据；不提供虚构的“提升转化率／效率百分比”。案例只用于分析公开设计决策，**不宣称完成这些网站的实时全站视觉、性能或无障碍审计**。

访问限制也影响证据：Material 3 和部分 Apple HIG 页面依赖 JavaScript，未完整取得正文；Apple 材质分析采用可读取的 WWDC25 官方文字稿。Cohere 品牌公告只用于核验发布日期，设计分析采用 Pentagram 的项目说明。[^M05][^J09][^J06][^J07]

### 0.3 同一品牌，不同任务：不要把营销页做成后台，也不要把后台做成海报

以下是综合设计系统与案例得到的工作区分，而非所有产品必须遵循的模板。[^T02][^D03][^J05]

| 决策 | 营销页／落地页 | Web 应用界面 |
|---|---|---|
| 首要问题 | 用户能否理解价值、相信证据、知道下一步？ | 用户能否定位对象、比较信息、完成与恢复操作？ |
| 排版与密度 | 可用有性格的大标题、节奏变化和叙事留白 | 倾向稳定的标题、标签、表格和紧凑但可读的密度 |
| 主要动作 | 一个决策区域突出一个转化方向；长页可重复同一 CTA | 不同工作区域可各有主要操作，不要求全应用只有一个主按钮 |
| 视觉材料 | 品牌摄影、插画和表达性动效可以承担论证或记忆功能 | 状态、数据、导航和操作优先；装饰不应挤压任务内容 |
| 成功证据 | 理解测试、首击位置、线索质量与适当的转化实验 | 任务完成、错误与恢复、查找和比较效率、重复使用成本 |
| 共同底线 | 真内容、语义结构、清晰状态、响应式、可访问性、性能 | 同左；品牌不同不能成为破坏底线的理由 |

## 主线一：设计方法论——可以验证的规则与约定

### 1.1 从任务到层级：经典原则的可执行版本

CRAP 指 Contrast、Repetition、Alignment、Proximity，分别为对比、重复、对齐与亲密性。它们是组织关系的框架，不是四个装饰技巧。Williams 的经典教材和 Refactoring UI 的公开实践是主要依据；下面的具体检查为本报告转译。[^C01][^C02][^C03]

| ID／性质 | 原则与操作 | 判断方法 | 反例／边界 |
|---|---|---|---|
| M01 · C/J，B/C | **先写任务与信息优先级。** 列出页面对象、用户要做的决定、必须知道的证据；再画结构 | 不看样式，能否解释每个模块帮助哪个任务；删掉后是否损失必要信息或明确品牌表达？ | 展览／艺术网站的体验本身可以是任务，不应强制变成 SaaS 漏斗 |
| M02 · C/J，B | **让对比对应重要性。** 用字号、字重、位置、空间和色彩共同区分主次 | 将所有高强调元素列出，每个是否有理由；同一决策区域是否有互相抢夺的主动作？ | 不靠把次要文字降到不合格对比度建立层级；危险操作也不必永远最醒目 |
| M03 · C，B | **重复语义，而非重复外壳。** 同类对象、同级标题、同种状态采用相同规则 | 跨页面并排比较同一角色，尺寸、用词、交互和状态是否一致？ | 不同数据关系不应为了“统一”全部塞进相同卡片 |
| M04 · C/J，B | **建立少量明确对齐线。** 按阅读方向对齐正文、标题、控件与数据 | 在截图上画出主要起始边和基线；例外是否用于真实层级或光学校正？ | 圆形图标与文字有时需要光学校正；RTL 界面不能盲目强制左对齐 |
| M05 · C/J，B/C | **用距离表达分组。** 相关元素的组内距通常小于组间距 | 不加边框时，标签仍靠近自己的输入框、标题仍靠近自己的内容吗？ | 2 倍间距只是可选约定；大型编辑器的空间约束可能需要其他分组线索 |
| M06 · C/J，B/C | **先表达阅读顺序，再设计阅读动线。** 标题先概括，证据再支撑，操作位置可预测 | 让未参与设计的人指出主标题、关键证据、下一步；记录误认位置并调整 | “F 型”“Z 型”不是必套模板；图像浏览、明确任务和不同语言会改变扫描方式[^J01][^J02] |

可以做一次简短的遮挡／回忆测试：短暂展示页面后询问“这是什么、主要信息是什么、下一步是什么”。这是低成本形成性检查，**不是通用的五秒合格标准，也不能代替任务测试**。

### 1.2 排版：先保证阅读，再建立性格

| ID／性质 | 决策与建议起点 | 可核验标准 | 常见反例与依据 |
|---|---|---|---|
| T01 · C/J，B | 先选字体角色：正文／界面、展示标题、代码或数据；默认少量角色，明确中西文字体回退 | 检查真实中英文、大小写、数字、标点、所需字重与加载失败；不靠浏览器伪粗体制造关键层级 | “必须定制字体”“系统字体没有品味”均不成立；可读性和有意选择比新奇更重要[^T03][^T04][^J10] |
| T02 · C，B/C | 建立有名字的字阶与用途，如 caption/body/label/section/display；样例尺度可为 12/14/16/20/24/32/48px，按内容调整 | 同角色复用 token；相邻层级在真实内容中可辨；字号变化能解释用途 | 不能把这个样例当行业标准或所有角色都必须用满；不要以黄金比例替代检查[^T01][^C02] |
| T03 · C/J，B | 按阅读任务选基础字号，而非一律追求大字或小字 | 正文、密集表格、帮助文字分别测试；放大后仍完整；核心任务不依赖难以辨认的细小字 | Carbon 的 productive 基准为 14px、expressive 为 16px；WCAG 没有通用最小字号，14px 不自动合格，16px 也不自动合格[^T01][^T04] |
| T04 · C/J，B/C | 本报告建议长段落行高从拉丁文约 1.5–1.7、中文约 1.6–1.8 试起；标题按字体适度收紧 | 检查连续多行、标点、重音、上下延伸部和中西混排是否碰撞；行距不破坏段落分组 | 这些是起点，不是 WCAG 默认行高要求；单行控件与展示标题不必照搬[^T03][^T05] |
| T05 · C/J，B/C | 按语言限制行长。USWDS 对英文给出约 45–90 字符、长文约 66 字符的建议；中文可先试约 28–40em 的桌面正文栏宽，再实读调整 | 实际数数、阅读连续段落并观察回行；移动端允许更短，不为凑字符数缩字 | `65ch` 只是近似宽度，不等于任意字体 65 个字符；不能把英文行长直接复制为 65 个汉字[^T03][^T05] |
| T06 · C，A/B | 对齐用于比较的数值，统一单位、精度与本地化；需要时启用 `font-variant-numeric: tabular-nums` | 检查字体是否支持等宽数字；同列数值右对齐或按小数点对齐；空值、负数、千分位、货币有规则 | 等宽数字本身不会实现小数点对齐；装饰性等宽字体也不必用于所有正文[^T06][^T07] |
| T07 · C，B | 为中文及混排处理语言、标点、换行与基线；给页面和局部内容正确 `lang` | 检查行首／行尾禁则、引号括号、单位断行；长网址局部换行；不要全站 `word-break: break-all` | 中文排版需求是重要参考，但当前 CLREQ 为 Group Note Draft，不能宣称其中每项都是 WCAG 强制要求[^T05] |

**文字处理细节。** 不要用手敲多个空格对齐数据；不要把关键信息烘焙进图片；长标题不能仅靠固定高度和裁剪“保持美观”。标签、标题和正文的视觉尺寸可以独立于 HTML 语义，但语义标题仍应表达文档结构。局部大写、加字距或斜体可以用于品牌表达，却不应无差别施加到长段落。以上是阅读与结构优先的实现建议，须用真实内容而非短占位文字验收。[^T03][^T05][^A01]

**文本间距的关键澄清——R，AA，证据 A。** WCAG 1.4.12 要求：在所用标记语言支持的情形下，用户把行高设为字号 1.5 倍、段后距设为字号 2 倍、字距设为 0.12 倍、词距设为 0.16 倍时，不丢失内容或功能。它测试的是**容忍用户覆写**，不是要求作者默认同时设这些值；不使用相关间距概念的语言／书写系统只需支持适用项。应实际注入测试样式，检查导航、按钮、标签和弹窗，而非只查看正文。[^A05]

### 1.3 色彩：先定义角色，再构建色板

#### V01 · 语义配色体系——C，证据 B

建议先列角色：`canvas / surface / text-primary / text-secondary / border / action / on-action / focus / success / warning / danger`，再为浅色、深色及交互状态分配色值。品牌色不等于所有主要文字颜色，错误色也不等于一切醒目色。检查相同语义是否复用角色、不同语义是否被误设为同色同形。Carbon 的主题机制是实践依据，但具体层级与命名可由项目选择。[^V02]

“中性色打底＋有限强调色”是控制竞争的常用起点，不是必须遵守的 60/30/10 公式。编辑、娱乐和文化品牌可能需要更丰富色彩。Stripe 2019 年案例说明，色板还应兼顾感知与可访问性：其探索使用 CIELAB，并非简单等差 HSL，也不是后来工具文案常写的 OKLCH。采用任何感知色彩空间都**不能免除最终对比度验证**。[^V01]

#### V02 · 可量化的对比与非颜色线索——R，证据 A

| 条款 | 必须正确使用的要求 | 如何测量／容易误读处 |
|---|---|---|
| 1.4.3，AA：文本 | 一般文本与背景至少 **4.5:1**；大文本至少 **3:1** | 大文本通常为至少 18pt，或至少 14pt 粗体，约为 24／18.67 CSS px；CJK 可按条款等效字号解释。不能把所有 18px 文字算大文本；不确定时按 4.5:1[^A02] |
| 1.4.11，AA：非文本 | 用于识别必要控件、状态或理解图形的视觉信息，相对相邻颜色至少 **3:1** | 不是所有装饰边框、阴影都要 3:1；禁用控件与未修改的浏览器默认外观存在适用例外[^A03] |
| 1.4.1，A：使用颜色 | 颜色不能是传达信息、动作或区分状态的唯一视觉手段 | 错误同时给文字／符号，图表给标签／线型／纹理；不能只说“点击绿色按钮”[^A04] |

按**实际合成后的背景与状态**测试：浅／深色、悬停、选中、焦点、错误、图片与渐变底。文字跨越变化背景时，不要拿整图平均色计算；检查实际字形所在区域的最不利组合。不要将 4.49 四舍五入称为通过 4.5；细字重即便数值达标也可能需要更高的实际可读性余量。[^A02]

#### V03 · 深色模式与材料——C/J，证据 B/C

不要把深色模式实现成全局反相或简单把白底换黑。重新分配表面层次、文本强弱、图表颜色、边界和焦点，分别校验对比。用同一组件在两个主题中的所有状态作对照，检查选中与错误是否仍能辨认。纯黑、纯白并非禁用色；问题是眩光感、边界丢失、图像适配或层级不清等具体结果。[^V02]

透明、模糊、渐变会使最终背景依赖内容；须提供足够稳定的文字承载面及不支持效果时的回退。Apple 对 Liquid Glass 的说明强调其导航／控制层角色，并提醒避免将其用于内容层或玻璃叠玻璃；这支持“材料要有结构角色”的判断，**不代表应把所有 Web 组件换成玻璃**。[^J09]

APCA 可作为附加感知评估工具，但不能代替声称符合 WCAG 2.2 时所需的规范对比计算。本报告不把尚有争议的感知评价工具写成既成的替代标准；方法提出者对未来标准的描述不等于现行规范事实。[^A01][^V03]

### 1.4 布局：网格表达关系，响应式保护任务

| ID／性质 | 原则 | 判断方法 | 反例／边界 |
|---|---|---|---|
| L01 · C，B | 用网格约束主要对齐、容器宽度与列关系；根据内容决定列数 | 标题、正文、媒体、表格、导航是否共享明确锚点；没有意义的偏移是否可消除？ | 12 列不是真理；Carbon 使用 16 列布局。经典网格思想不等于某个 CSS 框架[^C04][^L02] |
| L02 · C，B | 建立有限间距尺度，例如 4/8 为基础，并定义组内、组间和页面边距用途 | 从代码或设计稿抽取实际间距，重复用途是否复用 token；例外是否记录？ | 1px 边框、2px 光学修正合理；CSS px、设备像素、原生平台 pt 不能混称为同一种 8pt[^L01][^A08] |
| L03 · C/J，B/C | 用留白区分段落和操作群组，不把“空”当目标 | 删除多余空白后是否反而更好比较数据；增加空白是否真正减少混淆？ | 专业表格可高密度且高质量；营销 hero 的空间节奏不应复制到每个后台列表[^T02][^J05] |
| L04 · C/J，B/C | 根据关系选择容器：独立对象可用卡片；跨行比较优先表格；顺序信息优先列表 | 每个卡片边界能否说清对象或交互范围；把卡片改成行后，比较是否更容易？ | 卡片很适合商品、作品和独立任务；问题是无差别卡片化，不是卡片本身[^C03][^J04] |
| L05 · C，B | 由内容失效点选择断点；允许字号、列数、导航与密度分别调整 | 连续缩放，而非只看几个设备预设；检查长标签、长数字、翻译、侧栏和弹窗 | 框架断点是起点；移动端不能仅靠隐藏关键列、截掉功能实现“适配”[^L03] |
| L06 · R，AA，A | 保证适用内容在等效 **320 CSS px** 宽度重排，不因阅读而需要双向滚动 | 可用 1280 CSS px 视口在 400% 缩放后检查等效宽度；文本另做 200% 调整测试 | 这不是“320 宽再放大 400%”。真实二维表格、地图等可有例外，应局部滚动，不能让整页横溢[^A07][^A06] |
| L07 · C，B/C | 在真实数据和全部状态下确定高度、换行、溢出规则 | 用最长标题、空集合、大数值、验证错误及慢加载测试；避免固定高度吞内容 | 截断可用于有完整访问途径的摘要，不能把用户必须知道的错误／数值永久截掉[^A05][^A16][^A17] |

建议项目回归宽度包含 320、360、768、1024、1440 CSS px，并在其间拖动窗口寻找破点。**这只是本报告提供的测试样例，不是 WCAG 或设备市场分布结论。** 顺序与导航变化必须同时检查 DOM 阅读顺序，不用 CSS 视觉重排制造键盘顺序错乱。

### 1.5 动效：解释变化，不让用户等待装饰

#### M07 · 功能与表达分开——C/J，证据 B/C

先为每个动效写一句用途：确认操作、解释空间关系、保持对象连续性、呈现状态，或承担明确的品牌叙事。无法说明用途而又持续抢注意、阻塞输入的动效应删除。品牌短片与交互展览可以需要装饰／表达动效；高频审批表单通常更需要即时反馈。Carbon 明确区分 productive 与 expressive motion，支持按情境而非按流行统一加动效。[^M01]

**时长和缓动的项目起点，不是行业强制值：** 本报告建议微反馈先试 120–180ms，面板展开先试 180–280ms，较大场景过渡先试 240–400ms；再按距离、尺寸、输入频率和设备调整。进入／确认常适合减速结束，退出常适合加速离开，持续等速进度可以线性；不默认给所有元素加弹簧或回弹。检验时记录动作到反馈的延迟、连续快速操作是否积压、动画结束前能否继续任务。上述数值是证据 C 的调参起点，**不是对 Material 或 Apple 规范的转述**。[^M01]

Material 3 当前可检索的 motion 文档已经区分 physics 与 legacy easing/duration，进一步说明不宜把旧版某个 200／300ms 参数写成永恒通则。本次未完整读取其 JS 页面，因此不转录新的物理参数。[^M05]

#### M08 · 降级与自动播放——R/C，证据 A/B

响应 `prefers-reduced-motion`，移除非必要视差、缩放和持续移动，保留必要的状态信息。测试应直接启用系统／浏览器偏好，完成原任务。不要用无差别 `* { animation: none }` 隐藏本应出现的内容，也不要让业务状态依赖 `animationend` 才完成。尊重该偏好是本报告的默认质量约定；相关 WCAG 2.3.3“可关闭非必要交互动效”是 **AAA**，不能误写成专门的 AA 条款。[^M02][^A21]

对自动开始、持续超过 5 秒、与其他内容并行显示的移动／闪烁／滚动内容，WCAG 2.2.2 A 要求提供暂停、停止或隐藏，必要活动存在例外。**自动更新内容另有条件，不享有简单的“不到五秒即可不管”豁免。** 闪光还要另查 2.3.1；最稳妥的项目策略是避免非必要闪烁。[^A22][^A01]

#### M09 · 性能预算——C，证据 A/B

优先考虑 `transform` 与 `opacity`，但不要宣称它们必然“GPU 加速且零成本”。大面积模糊、阴影、合成层和主线程脚本仍可能卡顿；谨慎使用 `will-change`，在性能／绘制工具中观察实际路径。不要为每个滚动段落加载重型动画依赖，也不要让 preloader 等装饰阻挡可用内容。[^M03]

采用 Core Web Vitals 时，现行良好阈值为 **LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1**，按真实访问的第 75 百分位评价，并区分移动与桌面。单次本地 Lighthouse 不等于真实用户分位数；这些指标也不是整个应用任务效率或审美评分。没有现场数据时应报告“实验室结果／现场数据待验证”。[^M04]

### 1.6 设计系统：统一决策，而非统一所有长相

#### D01 · 从值到语义到组件——C，证据 B/C

推荐分为原始值、语义角色、组件用途三层，例如：

```text
palette.blue.600 → color.action.primary → button.primary.background
space.3         → space.control.inline → button.padding.inline
```

这是本报告推荐的架构，不是 DTCG 强制要求三层。检查主题切换是否主要改变映射、组件是否绕过 token 随意写色值、同名 token 是否在不同页面被赋予矛盾含义。允许少量明确记录的特殊值，避免为了“零硬编码”反而制造无意义 token。[^D01][^V02]

DTCG **2025.10** 是 2025-10-28 发布的首个稳定格式版本；它明确不是 W3C Standard，也不在 W3C Standards Track。可用它提升 token 交换一致性，但不能把“采用该格式”当作完整设计系统或无障碍证明。[^D01]

#### D02 · 组件契约与治理——C，证据 B/C

每个交互组件至少定义：用途和禁用场景、结构、尺寸与密度、文字规则、交互行为、可访问名称、键盘与焦点、加载／空／错误／禁用／成功状态、溢出、主题和本地化。验收时看状态矩阵而非单张默认截图。GOV.UK 的按钮规范展示了“外观＋用法”的组合，不只是给一个 CSS 类。[^D03]

本报告建议为系统设维护责任人、版本与变更说明、迁移／弃用规则、交互测试和视觉回归；其目的在于让修改可追踪。这些是工程治理建议，不声称某一种流程适合所有团队。不要把 Figma 文件、组件 npm 包或一页颜色表单独等同于设计系统。[^D02][^C02]

**验收点：** 抽样同一种输入框、错误、弹窗和按钮，跨三个页面对比；如果样式一致但行为不同，仍属一致性缺陷；如果营销页与应用的密度不同但语义和品牌一致，不应机械“统一”它们。[^T02][^D03]

### 1.7 无障碍：不能用静态截图完成的质量检查

以下为设计相关的重点条款，**不是完整 WCAG 2.2 AA 清单**。达到 AA 还需满足所有适用的 A 与 AA 条款；本报告不是法律意见，也不对任何未测试产品作合规声明。

| 内容／等级 | 可操作检查 | 重要边界与依据 |
|---|---|---|
| 键盘：2.1.1 A；无陷阱：2.1.2 A | 不用鼠标完成主流程；检查 Tab、Shift+Tab、Enter、Space 与适用的方向键；能退出每个区域 | 不要给每个普通元素都加 `tabindex=0`；模态内合理循环焦点且可退出，不是非法陷阱[^A13][^A01] |
| 结构与名称：1.3.1 A、4.1.2 A | 用可访问树／读屏检查区域、标题、标签、表头、名称、角色、状态；优先原生元素 | `role="button"` 不自动获得按钮键盘行为；ARIA 不是补完错误 HTML 的魔法[^A14][^A24] |
| 焦点：2.4.3 A、2.4.7 AA、2.4.11 AA | 焦点顺序与任务匹配、可见；滚动后获得焦点的组件不能被 sticky header／弹层完全盖住 | AA 的“不完全遮住”不等于“全部可见”；项目可主动采用更强要求。不要只测焦点环而漏掉组件遮挡[^A10][^A11] |
| 焦点外观：2.4.13 AAA | 采用增强目标时，检查指示区域至少相当于未聚焦组件或其子组件 2 CSS px 厚周长面积，且聚焦前后相同像素对比 ≥3:1，按条款处理例外 | “2px 描边”不是所有情形下充分条件，也不是 AA 统一强制值；与相邻颜色的非文本对比要求要分开理解[^A12][^A03] |
| 指针目标：2.5.8 AA | 一般目标至少 24×24 CSS px；不要只看图标外观，应测实际命中区域及形状 | 小目标可满足间距、同行文字、同页等效控件、未修改浏览器控件或必要表现等例外。间距例外按每个小目标中心直径 24px 的圆是否与其他目标／小目标圆相交判定，不是笼统“旁边留 24px”[^A08] |
| 增强目标：2.5.5 AAA | 触控可把 44×44 CSS px 作为更舒适的项目起点，保留条款例外 | 44×44 不是 AA 的统一门槛；也不能把 Apple 的原生 pt 直接当作 CSS px[^A09] |
| 文字与重排：1.4.4、1.4.10、1.4.12 AA | 文本调整到 200%；检查 320 CSS px 等效宽度；执行文本间距覆写 | 三项是不同测试，不要以“做了手机适配”替代；真实二维内容按例外处理[^A06][^A07][^A05] |
| 表单：3.3.2 A、3.3.1 A | 保留可见标签和必要说明；提交失败时标明字段及文字原因；输入后仍能知道字段含义 | placeholder 不能单独承担持久标签；错误不只变红，修正建议在可行时给出[^A16][^A17] |
| 状态：4.1.3 AA | 保存、结果数量、失败等适用状态可被辅助技术识别，不需要用户主动寻找 | 根据紧急程度使用恰当状态机制；不要让每个数字刷新都抢占朗读，也不要无理由搬移焦点[^A15] |
| 悬停／焦点内容：1.4.13 AA | 检查适用的额外内容能关闭、能移入、能持续显示；核心操作提供键盘和触控路径 | 不能把必要说明仅放在鼠标悬停；遵循条款对浏览器原生提示等的条件与例外[^A18] |
| 拖动：2.5.7 AA | 给排序、移动、范围选择提供非拖动的单指针操作，如“上移／下移”按钮 | 仅提供键盘替代并不能单独满足这项单指针要求；必要拖动／未修改用户代理功能可例外[^A19] |
| 登录：3.3.8 AA | 允许密码管理器、自动填充、粘贴或合适替代，避免无辅助地强迫记忆／转录 | 该条有替代、辅助机制、对象识别等适用例外，不应简化成“任何认知测试绝对禁止”[^A20] |

**模态对话框的完整行为。** 打开后把焦点放到适合任务的位置；Tab 留在对话框内；背景不可交互；提供适当关闭方式；关闭后通常返回触发点，若触发点已不存在或工作流推进则选择合理下一位置。初始焦点不一定是第一个输入框：长结构内容、破坏性确认等需要不同策略。仅写 `aria-modal="true"` 不会自动实现这些行为。[^A23]

至少对一套有代表性的浏览器／读屏组合做真实流程检查；自动检测补充而非替代键盘、读屏、认知顺序与内容判断。工具没有报错，只能说明“该工具的这组检查未发现问题”。[^A25]

## 主线二：美学与品味——把“好看”拆成可指认的决策

### 2.1 观察什么，不观察什么

以下采用目的性案例选择：应用界面看 Linear；品牌与营销表达看 Pentagram／Cohere、Stripe；跨渠道任务看 Work & Co／IKEA；可复用基础看 Carbon 与 GOV.UK；用 Awwwards 理解创意展示的评价倾向。**这不是“全球最好网站”排名，不是随机样本，也没有比较这些产品的真实转化或留存。**

Awwwards 公开的评审权重为设计 40%、可用性 30%、创意 20%、内容 10%。因此它适合发现艺术指导、表达手法和互动创意，但获奖本身不能证明 WCAG、性能、业务转化或复杂应用效率。观看获奖作品时应分别问“值得借鉴的表达是什么”和“我们的用户是否承担得起这种交互成本”。[^J03]

### 2.2 一方案例：借鉴决策，不复制皮肤

| 案例、日期与事实 | 可迁移的设计判断 | 核验方法 | 不应推导的结论 |
|---|---|---|---|
| **Linear，2024-03-28。** 团队说明其重设计调整侧栏、标签页、标题区和面板，处理噪声、对齐与密度，并提高内容对比、改进主题生成[^J04] | 应用的辨识度可以来自精确关系与一致细节，而不只是强烈装饰 | 并排比较各页面相同层级、面板起始线、内容与导航强调；检查更改是否使任务信息更好辨认 | “高级应用必须小字浅灰”“复制黑底细线就获得 Linear 品味” |
| **Linear，2026-03-12。** 新一轮调整强调更平静的界面及更一致的页面框架／操作位置[^J05] | 频繁使用的工具需要可预测性；让导航退后不等于让它难读 | 跨多个视图寻找同一种动作；检查是否稳定出现在同一结构角色，且仍可访问 | 一方设计意图不等于已证实任务速度提升，也不代表所有应用都应采用同一布局 |
| **Pentagram／Cohere，品牌于 2023-03-29 公开发布。** 设计体系把自然与技术的联想贯穿字体、颜色、图形及网站／产品触点[^J06][^J07] | 品牌特色来自一组同方向的选择，不能用随机紫色渐变替代品牌概念 | 将网站、产品、图形和文字并排；能否指出共同的形状、排版、色彩逻辑？ | 不能把“自然风”变成所有 AI 产品的新模板；该历史案例不代表其 2026 年网站逐像素外观 |
| **Stripe，2019-10-15 色彩系统案例。** 团队将可访问性与感知色彩组织一起考虑[^V01] | 饱和色与表达性品牌可以和可验证的色彩角色并存 | 对核心色板写出允许的文字／背景配对，逐一验证，而非只展示漂亮色块 | “渐变必然低级”“一套等亮度色板自然全部达标”；材料效果不免除文字对比测试 |
| **Carbon／GOV.UK，持续维护。** 文档同时规定视觉、结构与用法，排版依语境调整[^T02][^D02][^D03] | 可靠、朴素、明确也是一种成熟审美：让界面准确表达服务 | 检查按钮文案能否预测动作、字段是否有标签、同语义组件是否复用、密度是否适配任务 | 品味不是越像创意工作室官网越好；也不能以“政府／企业风格”为由忽略品牌和细节 |
| **Work & Co／IKEA，项目页未标发布日期。** 其公开案例涉及网站、内部工具及移动体验的协同[^J08] | 风格一致应服务跨渠道任务连续，而不是所有屏幕视觉完全相同 | 从查找商品到相关操作检查术语、对象和状态是否衔接；保留不同设备的合理交互差别 | 案例中的营销成绩不能在缺少控制变量时用作某种视觉风格的因果证明 |

从这些来源可归纳出若干**证据 B/C 的共同倾向**：关系清楚、排版有角色、品牌元素可解释、细节跨状态一致、装饰不破坏任务。它们是观察后的综合判断，不是“高质量网站都必须具备某种固定外观”的统计规律。

### 2.3 “高级感”的八个可操作维度

“高级感”不是独立于文化、行业和受众的客观属性。下表将其转成可以讨论的设计决策；判断性质均为 **J，证据 B/C**。每一项都给出反例，防止 agent 把建议机械化。

| 维度 | 具体做法与判断依据 | 可核验的判断 | 反例／边界 |
|---|---|---|---|
| **注意力分配有意图** | 让最高强调服务最重要信息；依据层级与动作规范[^C03][^D03] | 标记最醒目的文字、色块、图像，它们与任务优先级是否吻合？ | 节庆／娱乐内容可有多焦点；不能按企业后台的标准强制低刺激 |
| **比例与间距有关系** | 留白区分层级，页面边距、列宽和组间距协调；依据网格与间距体系[^L01][^L02] | 相同关系是否有相同间距；异常是否为了内容、光学或品牌？ | 全部扩大 padding 并不会自动改善；交易表格可能需要更紧凑 |
| **排版完成度高** | 标题、正文、数字、标点、混排分别处理；依据阅读和语言要求[^T03][^T05][^T06] | 使用真实长文与长数字后，字阶、断行、基线是否仍成立？ | 大衬线标题很适合某些编辑品牌，但不是每个工具的答案 |
| **材料有层级而非堆料** | 阴影、边框、模糊和透明度分别承担层次或交互角色；依据材料说明[^J09][^J13] | 逐个移除效果：是否损失层级、可供性或明确品牌表达？没有则优先删 | 有叙事功能的丰富材质不该仅为“简洁”被删除 |
| **品牌不是模板换色** | 从内容、语言、图形到排版共享一个可说清的方向；依据 Cohere 体系案例[^J06] | 不看 logo，能否指出本项目的具体特征及其业务理由？ | 政务表单不必刻意原创每个控件；熟悉性本身有价值 |
| **图像不是填空** | 选图与裁切说明具体产品、情境或概念，而非仅填满空白；由品牌案例综合推导[^J06][^J08] | 每张图回答了哪个问题；裁切是否丢掉关键信息；窄屏是否仍成立？ | 抽象图形可以表达品牌，不必所有图像都像说明书，但应有解释 |
| **细节在状态中成立** | 悬停、聚焦、加载、空态、错误、选中都遵循同一逻辑；依据组件与焦点规范[^D03][^A10][^A17] | 不只看默认截图；切换状态后位置、文字、对比和行为是否协调？ | 流畅淡入不能补救没有错误恢复路径的表单 |
| **表达成本合理** | 让表现性效果与加载、输入、滚动成本相称；依据动画与性能实践[^M03][^M04] | 在目标设备看输入延迟和绘制；关闭效果后，任务是否更顺畅且品牌几乎无损？ | 艺术体验可预算更多渲染成本，但应告知、降级并保留必要访问路径 |

一个实用评审方式是：让两个方案使用**同一内容、同一数据、同一状态**，再比较信息优先级、品牌一致性与任务完成。不要让一个方案用精修摄影，另一个用占位文字，却把差异全部归功于布局。这里的比较方法是本报告建议，并非已完成的用户实验。

### 2.4 主要风格语言：特征、适用场景、风险与反例

风格可以混合，也会复兴；下表不是线性进化史。经典网格著作证明网格思维早于今日前端框架，现代风格文章则提供术语边界；**不能据此推导“新风格一定优于旧风格”**。[^C04][^J11][^J12]

| 风格语言 | 可辨认的设计决策 | 较适合的任务／情境 | 必须检查的风险与反例 |
|---|---|---|---|
| **网格／国际主义取向** | 稳定对齐、明确比例、排版主导、装饰服从组织 | 内容密集、编辑、专业品牌、长期维护的系统 | 检查移动端与长内容；不把 12 列、无衬线或绝对对称当身份认证。网格可支持不对称[^C04][^L02] |
| **极简／朴素界面** | 少量强调、有限材料、删去重复线索，保留关键内容 | 任务工具、阅读、服务流程，也可用于品牌 | 检查标签、边界、焦点、空态是否被删没；“低对比＋大留白”不是极简的必要条件[^D02][^C03] |
| **编辑性／字体驱动** | 具有性格的标题、长短节奏、图文关系与明显版面层次 | 媒体、文化、品牌故事、内容营销 | 正文必须可读；长标题、中文和窄屏不能崩。展示性字阶不宜统治后台每个面板[^T02][^T03] |
| **Brutalism，粗粝／原生感** | 显露 HTML 与链接、朴素结构、反精修或原始感；不一定高饱和 | 艺术、实验、档案、作者型网站 | 检查是否“有意精确”而非“没完成”；作者说明中也有以默认字与极少 CSS 达到克制的案例[^J10] |
| **Neobrutalism，新粗野主义** | 粗边框、硬阴影、鲜明块面、强烈对比、直接的视觉重量 | 个性鲜明的产品、创意／文化营销、部分轻量工具 | 长时间任务可能受视觉噪声干扰；不是原始 HTML 风的同义词，也不必然不可访问[^J11] |
| **Glassmorphism／玻璃材料** | 半透明、模糊、浮层、背景参与材质表达 | 有清晰层级的导航、控制浮层、特定品牌场景 | 测最不利背景、无模糊回退和性能；内容全玻璃、玻璃层层叠容易破坏阅读[^J09][^J13] |
| **Skeuomorphism／拟物** | 借真实物体的形状、材质与操作联想解释数字功能 | 音频、仪表、创意工具、特定学习与品牌体验 | 检查隐喻是否真的熟悉，是否遮蔽功能；旋钮也需非拖动输入。拟物不是“越像照片越好”[^J12][^A19] |
| **Neumorphism／新拟物软浮雕** | 近似底色、明暗软阴影、凸起或凹陷 | 小范围材质表达与低密度展示 | 若仅靠低对比阴影区分控件／状态，风险高；可通过明确标签、边界和状态改善，不宜笼统宣称所有实现必然违规[^J16][^A03] |
| **沉浸式／3D／运动叙事** | 场景化视角、大媒体、连贯转场或空间探索 | 产品演示、活动、品牌故事、艺术体验 | 检查资源、输入延迟、减少动态效果与替代路径；不把登陆、表单或高频表格变成强制动画秀[^J15][^M02][^M03] |

### 2.5 趋势生命周期：判断“该淘汰什么”，不要宣判颜色死亡

可以把趋势分成三层：

| 层次 | 例子 | 更新策略与验证 |
|---|---|---|
| **长期任务原则** | 可读性、清晰关系、可预测交互、可访问性 | 长期保持，按新标准和用户反馈修正；不因新风格牺牲这些目标 |
| **可演化的系统约定** | 间距尺度、字阶、token 格式、动效参数、组件 API | 追踪系统版本并测试迁移；旧参数不是永恒真理，如 Material 当前对 physics 与 legacy 的区分[^M05] |
| **表现性语言** | 渐变、bento 排列、玻璃、粗边框、巨型标题、3D | 用品牌契合、任务收益、使用频率、竞争语境与成本评估；不设通用“过时年份” |

Stripe 的 2017 年表现性前端案例、Cohere 2023 年品牌体系和 Apple 2025 年 Liquid Glass 说明类似视觉材料会在不同用途下被重新组织。它们支持“需要分场景判断”，**不支持任何一项风格在 2026 年必然流行或必然过时的定量结论**。[^J15][^J06][^J09]

关于所谓“AI 风”：Anthropic 在 2026-03-24 的应用生成工程文章中，把通用紫色渐变、白卡片等列为其评估原创性时关注的现象；但那是特定厂商、任务与评估机制下的描述，不是跨模型发生率调查，也不是紫色不美的证明。对工具界面而言，盲目为原创而原创还可能损害熟悉性。[^J14]

**本报告建议淘汰的是错配，而不是材料：** 与业务毫无关系的抽象首屏、每页同样的三张卡片、为显得现代而降低对比、为截图漂亮而隐藏复杂状态。相同材料在有理由、可访问、性能可控的情境下仍可能是好选择。这一判断为 J/C，须用实际内容和替代方案验证。

## 主线三：常见错误——错误表现 → 为什么错 → 正确做法

以下 **40 项**是用于评审和生成后修正的风险清单，不是“AI 错误出现率”调查。原因引用前文原则或来源；修正是本报告的可操作建议。建议优先修复：**P0 可访问性／任务失败 → P1 内容与层级误导 → P2 品牌与表现细节**。某些视觉错误在具体产品中也可能升级为 P0。

### 3.1 生成界面常见的模板化与视觉错误

| # | 错误表现 | 为什么错：违反的原则 | 正确做法：可以执行的修正 |
|---|---|---|---|
| 01 | 不问品牌就套紫蓝渐变、光晕和“智能”星芒 | 风格没有任务或品牌依据，视觉强调可能抢过内容；不是颜色本身有罪。见 §2.5[^J14] | 先写品牌方向与强调角色；保留能解释意义的渐变，删除其余；对白底文字和渐变字分别验对比 |
| 02 | 用 emoji 代替全部导航、状态、工具图标 | 视觉字形和语气难统一，含义可能不明确；功能不能只依赖一个无名称图形[^A14] | 功能图标统一一套笔画／尺寸，并有可访问名称；emoji 留给适合的内容语气，不禁止有意使用 |
| 03 | 每句话一张卡，卡内继续套卡 | 边界不再表示对象关系，比较与阅读被切碎。见 L04 | 将连续内容改成正文／列表，多字段比较改表格；只给独立对象或明确交互边界用卡片 |
| 04 | 所有标题、长段正文、表单都居中 | 缺少稳定阅读起始线；表单与段落难扫描。见 M04、T05 | 短 hero 可以居中；长文和表单按阅读方向起始对齐，数据按比较任务对齐 |
| 05 | 巨型空泛口号占满首屏，真实产品解释在很远处 | 视觉权重与信息价值不匹配。见 M01、M02 | 将口号改成具体价值＋对象；紧接产品证据与下一步，不为凑视觉效果伪造数字 |
| 06 | 标题、标签、正文都 16px／同字重，或全部加粗 | 各角色无法辨认，层级塌陷。见 T02 | 定义 display/section/body/label 等角色；用尺寸、字重、空间区分，不只换颜色 |
| 07 | 用极浅灰细字制造“高级感” | 次要不等于不可读；可能违反文本对比要求[^A02] | 先恢复合格对比，再用字号、位置、间距降低竞争；对真实字体检查细笔画 |
| 08 | 随机混用圆角、阴影、渐变、描边与玻璃 | 不同材料争夺同一层级，无法预测边界意义。见 §2.3 | 为每种效果指定角色；无独立角色则合并或删除，比较同层组件状态 |

### 3.2 排版、内容与布局的初级错误

| # | 错误表现 | 为什么错：违反的原则 | 正确做法：可以执行的修正 |
|---|---|---|---|
| 09 | 未检查任何默认字体／配色，就直接交付 | 错在缺少验证，不在“默认”二字；可能有缺字、回退、权重与语义问题[^T04] | 保留合适的系统字体也可以；补齐角色、回退、真实字符、主题和对比验证，记录选择理由 |
| 10 | 多套图标混用，把小图标放大成主视觉 | 笔画、光学重量和细节等级不协调；放大不等于重新绘制[^C03] | 统一图标套系；按原设计尺寸使用，主视觉需要时采用适合大尺寸的独立图形 |
| 11 | 16/19/23/27px 等间距任意堆叠 | 相同关系呈现不同距离，破坏重复与亲密性。见 M03、M05 | 抽取间距，归并到项目尺度；光学校正单独标注，不强行改掉所有非 8 倍数 |
| 12 | 所有区域都巨大留白，后台一屏只见少量记录 | 套用营销叙事密度，增加查找和比较成本。见 L03 | 降低装饰性边距，保留组间区分；提供合理密度选项并测试控件命中区域 |
| 13 | 文章横跨超宽屏，或把英文行长照搬为汉字数 | 行长未按语言与字体实读，回行困难。见 T05 | 对正文单独设最大宽度；不要把主应用容器和长文栏宽绑定；分别实读中英文 |
| 14 | 为固定版面强塞 `<br>`、固定高度、`overflow:hidden` | 假设了唯一文本与视口，翻译、缩放、错误出现即丢内容[^A05][^A06] | 让高度随内容增长；仅在明确的展示标题场景局部控制换行，并测试其他语言和宽度 |
| 15 | 数值左对齐、精度和单位混乱，空值显示成 0 | 视觉比较与数据语义都被破坏。见 T06 | 统一格式规则；右／小数点对齐；区分 0、未知、不适用；必要时使用等宽数字 |
| 16 | 为填满布局捏造客户 logo、好评、增长数据或功能截图 | 装饰优先于信息真实性，制造错误信任 | 使用经确认的证据；开发示例明确标“示例数据”，上线前替换或删去，不通过假内容制造丰满 |

### 3.3 容器、响应式与信息结构错误

| # | 错误表现 | 为什么错：违反的原则 | 正确做法：可以执行的修正 |
|---|---|---|---|
| 17 | 每行强制三个等宽模块，不足就补一句空话 | 让几何对称决定内容，违反任务优先。见 M01、L01 | 按实际信息选一栏、两栏或不对称；删除无价值模块，保留真实信息层级 |
| 18 | 多条可比较记录改成大卡片，字段位置每张不同 | 无稳定比较轴，重复找标签。见 L04、T06 | 高频跨记录比较改表格；卡片适合图像或独立对象，统一字段位置 |
| 19 | 移动端靠隐藏关键字段、删除操作完成“适配” | 表面不溢出，实际任务缺失。见 L05 | 重新组织优先级；提供详情、列选择或局部滚动，确保关键任务仍可完成 |
| 20 | 给整个页面横向滚动，以此容纳所有桌面组件 | 破坏适用内容的重排；二维例外被扩大到全页[^A07] | 限制真正二维区域的滚动；正文、标题、表单仍按窄视口重排 |
| 21 | 只在 1440px 和一个手机预设看过截图 | 断点之间、长内容、缩放与横屏问题未验证[^L03] | 连续调整窗口，覆盖代表性宽度；加入最长文本、200% 文本和等效 320px 重排测试 |
| 22 | CSS 调换视觉顺序，却不检查 Tab／读屏顺序 | 看到的流程和操作的流程不一致。见 §1.7 | 优先调整合理 DOM 顺序，再用布局表达；逐项键盘及读屏检查，不用正数 tabindex 补乱序 |
| 23 | 为了玻璃质感让正文直接压在复杂透明背景上 | 阅读底色不可预测，可能失去对比与层级[^A02][^J09] | 为文本提供稳定承载面；限制玻璃使用层级，检查最不利背景与无模糊回退 |
| 24 | 产品名、图像、错误文字只用短占位内容验证 | 隐藏真实布局约束，状态一变即破版。见 L07 | 建立真实长度样本和边界数据；同时覆盖空、加载、失败、成功、权限不足和禁用 |

### 3.4 交互与无障碍错误

| # | 错误表现 | 为什么错：违反的原则 | 正确做法：可以执行的修正 |
|---|---|---|---|
| 25 | `outline:none` 后没有替代焦点；sticky 区盖住当前操作 | 键盘用户无法定位或看到获得焦点的组件[^A10][^A11] | 恢复可见焦点；调整滚动间距／布局避免遮挡；逐项 Tab 测试，不只检查截图 |
| 26 | 用可点击 `div` 模拟按钮，只有鼠标 click | 缺少原生语义、键盘与状态；ARIA 名称不能自动补齐行为[^A13][^A24] | 动作使用 button，导航使用有 href 的链接；确需自定义时完整实现相应交互模式 |
| 27 | placeholder 充当唯一标签，输入后不知道字段意义 | 丢失持久说明；可访问名称也可能不足[^A16] | 保留可见 label；示例格式放辅助文字，与输入关联，不让 placeholder 承担标签全部职责 |
| 28 | 错误只变红、成功只闪绿，未给文字或状态通知 | 颜色成为唯一编码，读屏可能不知道结果[^A04][^A15][^A17] | 给出明确文字及字段关联；按重要程度提供状态消息，不为普通成功强行移焦点 |
| 29 | 图标或文字看起来够大，实际命中区域只有细小字形 | 外观尺寸不等于可点击区域，邻近目标容易误触[^A08] | 扩大实际目标区域而非仅放大图形；检查相邻目标、复杂形状与适用例外 |
| 30 | 关闭、解释、菜单等只在 hover 出现或只能拖动 | 键盘、触控或不能精确拖动的用户缺少路径[^A18][^A19] | 提供聚焦／触控可访问的控制；排序给上移／下移等单指针替代，不只增加键盘快捷键 |
| 31 | 模态出现但焦点留在背景；关闭后焦点丢失 | 视觉和操作上下文脱节；背景仍可能被误操作[^A23] | 实现进入、内部循环、背景不可交互、适当关闭与返回焦点；针对长内容选合理初始位置 |
| 32 | 禁用按钮没有解释，报错后清空所有输入或只能重来 | 状态不帮助用户恢复，增加重复劳动。由标签／错误原则推导[^A16][^A17] | 说明未满足条件；保留安全且有效的输入；提供重试／撤销或下一步，不把禁用当唯一反馈 |

### 3.5 动效、工程与交付错误

| # | 错误表现 | 为什么错：违反的原则 | 正确做法：可以执行的修正 |
|---|---|---|---|
| 33 | 每个元素都浮入、缩放、弹跳，连续输入仍排队动画 | 表达性效果侵占功能反馈，产生等待。见 M07 | 只保留解释变化的动效；高频操作缩短或即时完成，允许中断，不把所有元素设同一时长 |
| 34 | 自动轮播、视差或跑马灯不能暂停；滚动被强制劫持 | 用户失去控制，且可能违反自动运动相关条款[^A22] | 优先普通滚动与静态内容；保留自动运动时提供合适控制，检查键盘、触控与减少动态效果 |
| 35 | 关闭全部动画后内容仍透明，或业务永远等不到 animationend | 动画被错误当成业务状态机，降级破坏功能。见 M08 | 状态先正确提交；动效只是视觉表现；在 reduced-motion 下直接到可用终态并跑完整流程 |
| 36 | `filter: invert()` 生成深色模式，图片和状态色一起反转 | 没有重建语义映射，品牌与识别信息失真。见 V03 | 定义主题 token；分别检查图像、层级、错误、选中和焦点，不以浅色达标代替深色测试 |
| 37 | 只建颜色变量；按钮、表单和弹窗在各页复制后各自修改 | 外观可能相近，行为和状态持续漂移。见 D01、D02 | 扩展排版、间距、动效及组件契约；共享实现与状态测试，合理例外有记录 |
| 38 | 首屏加载大视频、重模糊、多字重字体和动画库，但没有预算 | 表现成本可能拖慢内容与输入；不是“现代前端”必需[^M03][^M04] | 从核心内容与交互预算倒推资源；非关键媒体延迟加载，实际测绘制与用户输入，不盲目堆 will-change |
| 39 | 只提供理想数据和默认状态，宣称“界面完成” | 把静态构图误当可用产品，未验证任务与恢复。见 D02、L07 | 交付状态矩阵，测试空／加载／失败／成功／长内容／权限及键盘焦点；未测项目明确列出 |
| 40 | Lighthouse 高分或组件库“无障碍”就宣称全站合规 | 工具覆盖有限；组件正确不保证组合、内容和流程正确[^A25] | 结合人工任务、键盘、读屏及状态检查；记录工具、范围与未测项，不宣称未经审计的 WCAG 合规 |

### 3.6 两个完整的 before／after 推演

以下为**本报告构造的教学场景，不是实测案例或转化实验**。

**A．B2B 落地页。** Before：居中巨型“重新定义未来”，背景光晕持续运动；下方三张抽象卡片；四种实心 CTA；产品截图太小且真假不明。问题不是紫色，而是用户看不到对象、价值、证据和主动作。After：标题说明“为谁完成什么”，副标题交代机制／边界；放入经确认的产品界面及对应说明；按一个决策区域组织主要 CTA，次要动作降低视觉权重；用明确的品牌图形保留个性；窄屏、焦点及减少动态效果均可用。验收：陌生用户能否指出产品对象、核心价值、证据和下一步；事实是否均有来源；CTA 是否能完成对应动作。

**B．任务管理后台。** Before：统计、筛选、每条记录都各装一张大卡片；数据左对齐；悬停才出现更多操作；保存失败只闪红。After：页面标题和主要创建动作稳定；筛选靠近列表；适合比较的数据使用表格与统一数字格式；高频动作可发现；失败有文字原因、保留输入并提供重试；列表加载、无结果、空库和无权限分别说明。验收：用户能否不依赖鼠标完成创建／查找／修正；跨行能否迅速比较；不同状态是否清楚；移动布局是否保留必要信息。

## 4. 争议点、证据不足与明确不作出的结论

| 议题 | 本报告结论与证据强度 | 仍不能推导的结论 |
|---|---|---|
| 正文字号 | 无普适的 WCAG 最小字号；系统的 14／16px 是情境约定。A/B[^T01][^T04] | 14px 到处适合，或 16px 保证可读 |
| 4／8pt、字阶比例、行长 | 有稳定尺度有助于组织；具体数值为系统约定或建议。B/C[^L01][^T03] | 非 8 倍数必错；某个比例最美且适用于所有语言 |
| 原生指南移植 Web | 可借鉴语义、层级与材料用途，但输入方式、单位和实现须重新验证。B[^J09] | Apple／Material 的一个参数就是 Web 可访问性条款 |
| 44px、2px 焦点环、减少动态效果 | 需分别辨明 AA、AAA 与项目质量目标。A[^A08][^A09][^A12][^A21] | 把增强建议冒称为 AA 硬要求，或仅满足最低线就停止优化 |
| APCA 与 WCAG 对比 | 可以补充感知判断；WCAG 2.2 声明仍按现行规范。A[^A01][^V03] | 已有普遍生效的替代算法，或数值合格等于所有字体都舒适 |
| 风格优劣、颜色是否过时 | 必须讨论品牌、任务、语境与实现；缺少通用排名证据。B/C[^J09][^J11][^J14] | 极简天然高端、渐变天然低端、某风格永久过时 |
| AI 生成错误普遍性 | 存在一方工程观察与大量可解释的风险模式；本文未测跨模型频率。C[^J14] | “大部分 AI 都犯某错”的比例、模型优劣排名或必然因果 |
| 案例效果 | 一方材料可证明其设计意图与公开决策。A（事实）/C（迁移）[^J05][^J08] | 未经实验就声称这些决策提高了转化、留存或效率 |

## 5. 把研究用进开发：一套可重复的评审流程

这是本报告综合提出的执行流程，不是新的强制标准。

**生成前：** 确定页面属于什么任务；写真实内容和对象关系；继承既有品牌／系统，明确可改变的范围；选择功能性密度和有理由的表现方向；把 R、C、J 分别记入约束。不要先锁定“紫色 SaaS hero”再填内容。

**生成中：** 先完成语义结构、主要任务和真实状态，再组织排版与布局；将稳定决策写成 token 和组件契约；在至少一个窄屏与一个宽屏持续检查。不要等全部装饰完成才发现内容结构不成立。

**生成后：** 依次检查内容真实性与任务可达、键盘／焦点／表单、对比与目标、缩放／重排／文本间距、主题与全部状态、动效与性能，最后再比较品牌与艺术指导。只要 P0 项仍失败，就不把时间优先花在阴影和光晕上。

建议用下面的证据记录，而不是只写“已优化”：

```text
检查项：保存失败时，错误可见且可被读屏识别
条件：窄屏 / 深色主题 / 键盘操作 / 模拟保存失败
期望：字段与原因明确；已有输入保留；焦点逻辑合理；可重试
结果：是 / 否 / 未测试
证据：截图、操作记录、可访问树或读屏记录
修正：具体位置与实现变更
遗留：未覆盖的浏览器、设备或例外
```

**放行标准：** 所有适用的阻断项有证据地通过；例外有理由；未测项明确暴露。审美判断至少能回答“为什么这样设计、什么条件下不该这样设计、如何检查它是否成立”。配套 agent 指南将这些要求压缩为可注入的执行规则，但不能替代完整 WCAG 审计或真实用户研究。
